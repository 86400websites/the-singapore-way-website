# Launch Checklist

Three phases that take **The Singapore Way** from "feature-complete" to "live on `the-singapore-way-website.vercel.app` and verified".
Launch is a checklist, not an event — nothing goes live on a feeling.

*Status note: this site launched pre-SOP on the `vercel.app` domain — the course launch followed [`course-setup-and-launch-checklist.md`](./course-setup-and-launch-checklist.md). This checklist is deliberately kept UNCHECKED and must be run in full for the upcoming real-domain migration to `thesingaporeway.com` (tracked in the post-launch backlog).*

---

## Phase 1 — PRE-LAUNCH (days before; nothing here happens on launch day)

### Build completeness
- [ ] All MVP sprints merged to `main`; no sprint half-open.
- [ ] [`QA-CHECKLIST.md`](./QA-CHECKLIST.md) passed in full on the current `main` (both parts).
- [ ] [`SECURITY-CHECKLIST.md`](./SECURITY-CHECKLIST.md) passed in full — every blocking item resolved, not deferred.
- [ ] Post-launch items live in the backlog, not in your head.

### Content
- [ ] Real content everywhere — zero placeholder text, zero `[placeholder]` tokens, zero stock "lorem".
- [ ] The locked facts/numbers list verified: every exact claim the site makes is correct and identical site-wide.
- [ ] All images are final assets, optimized, with alt text.
- [ ] Content/CMS sites: editor roles, draft-review-publish flow, redirects, media ownership, backup/export, and client training are approved. (N/A for this project — no CMS. Blog posts are typed in-repo content in `src/data/blogPosts.ts`; course content lives in Supabase and is edited per [`update-course-content.md`](./update-course-content.md).)

### SEO basics
- [ ] Every page has a unique `<title>` and meta description.
- [ ] OG image set and rendering (test with a share-preview tool). (This project generates it from `opengraph-image.tsx`; known backlog item — the OG image hardcodes "thesingaporeway.com" text while production still serves from the vercel.app host.)
- [ ] Favicon + app icons present.
- [ ] `sitemap.xml` and `robots.txt` generated and correct (generated by `sitemap.ts` and `robots.ts` in `src/app/`).
- [ ] Canonical URL derives from the single public site-URL variable named in [`TECH-ARCHITECTURE.md`](./TECH-ARCHITECTURE.md) (`NEXT_PUBLIC_SITE_URL`) — not hardcoded.
- [ ] Key pages meet the approved performance budget recorded in [`QA-CHECKLIST.md`](./QA-CHECKLIST.md).

### Legal and tracking
- [ ] Legal pages live (privacy, terms, cookies — whatever the client's jurisdiction requires).
- [ ] Analytics installed IF agreed with the client — and covered by the privacy page. (This project ships PostHog analytics and Sentry error tracking.)

### Approval
- [ ] Client (Maher Kaddoura) has seen the full site on the production URL (or final Preview) — desktop and mobile.
- [ ] Client written launch approval received (email or message — in writing, dated).

**Why this matters:** the approval line makes launch the client's decision, on a site they have actually seen.

**Never do this:**
- Never launch with an unresolved security-checklist blocking item.
- Never launch with placeholder content "we'll swap later".

## Phase 2 — LAUNCH DAY

For this project, "launch day" means the future real-domain migration: connecting `thesingaporeway.com` while production currently serves from `the-singapore-way-website.vercel.app`.

- [ ] Backlog gate cleared first: `src/lib/request-origin.ts` hardened — recorded in the backlog as required before the real-domain migration.
- [ ] Connect `thesingaporeway.com` to the Vercel project `the-singapore-way-website` on Vercel; add only the provider-specified DNS records.
- [ ] Wait for DNS to propagate and SSL to issue — the padlock must be valid before you announce anything.
- [ ] Decide www vs apex as canonical; configure the other to 301-redirect to it.
- [ ] Update the site-URL env var (`NEXT_PUBLIC_SITE_URL`) in Production to the real domain, then redeploy
      (env changes do not take effect without a redeploy — public values are baked at build time).
- [ ] If auth is in use (it is — Supabase email/password + email links, no OAuth): add `https://thesingaporeway.com/**` to the Supabase redirect allow-list and update the Supabase Auth Site URL per [`SUPABASE-VERCEL-SETUP.md`](./SUPABASE-VERCEL-SETUP.md) —
      KEEP the old `https://the-singapore-way-website.vercel.app/**` entry listed for a grace period so existing email links still resolve. (While in there, clear the stale `localhost:5000` / `localhost:5173` entries left from the Replit/Vite era — backlog item.)
- [ ] Verify security headers on the LIVE domain response (`curl -I https://thesingaporeway.com`) —
      config reading is not deployed reality.

## Phase 3 — POST-LAUNCH SMOKE TEST (on the real domain, same day)

- [ ] Every page loads over https on `thesingaporeway.com` — click through the full sitemap.
- [ ] Primary conversion flow end-to-end as a real visitor: form validates, submits, confirmation shows. (This project tracks three conversions: course enrollment — sign up, then start the course; book purchase — `/thebook` outbound Amazon click; newsletter subscription via `/api/newsletter`.)
- [ ] Forms actually deliver: send a REAL test submission and confirm it arrives (inbox/dashboard/DB). (Newsletter must appear in the Mailchimp audience; contact must arrive at the configured Resend recipient inbox.)
- [ ] Mobile pass on a real phone: home, conversion page, one deep page. (Here: `/`, `/thebook` or `/online-course`, and a blog post or course lesson.)
- [ ] Canonical, og:url, sitemap URLs all show the new domain — nothing pinned to the old host.
- [ ] Search console: property added, ownership verified, sitemap submitted.
- [ ] No accidental `noindex` anywhere — check the live HTML head and response headers.
- [ ] Auth (if in use): sign up / sign in / reset on the live domain; email links land on `thesingaporeway.com`.

### The 48-hour watch
- [ ] Monitor errors (Vercel logs / Sentry) and form deliveries for 48 hours.
- [ ] Log every issue found to the post-launch backlog with severity.
- [ ] Fix via the normal workflow: branch → build → local checks → PR → deployed Vercel Preview → Codex review → merge → Production smoke test.

**Never do this:**
- Never hotfix directly on `main` in a launch-day panic — if production is broken, use [`ROLLBACK.md`](./ROLLBACK.md).
- Never mark launch "done" without a real test submission delivered.

Next step → if anything breaks in production, [`ROLLBACK.md`](./ROLLBACK.md). When the dust settles, [`HANDOFF.md`](./HANDOFF.md).
